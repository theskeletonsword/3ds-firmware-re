# 3DS FIRM/ARM Reversing — ARM11 and ARM9 Kernel Analysis

Analysis and reverse-engineering repository for the Nintendo 3DS firmware binaries (FIRM, `arm11.bin`, `arm9.bin`, sysmodules, `code.decompressed.bin`, `exheader.bin`).

> ⚠️ **CRITICAL WARNING:** Before testing critical drivers, modifying `FIRM` or writing to the storage of a 3DS console, **always make a full backup of the NAND and of the critical recovery files** (`movable.sed`, `otp.bin`, `seeds`, and copies of `FIRM`/`arm9.bin`/`arm11.bin`). Without a backup and without a recovery method (hardmod/NAND programmer), a mistake can cause an irreversible **hard brick**. See `3DS_DRIVERS_MANUAL.md` and `CRITICAL_DRIVERS_GUIDE.md`.

> **Notes column of the `.sym` tables:** originally Spanish; translated to English by `translate_sym_notes.py` (regex templates + `sym_notes_translation.tsv`). The Spanish originals are kept in `docs_es_backup/sym_notes_es/`. `extracted/` and `updates/` entries were renamed to English as well (`extracted/RENAME_MAP.tsv`).

> **Naming note:** directories under `decrypted_binaries/` were renamed to English and now use the **real module name from each ExHeader** (the old Spanish labels were often wrong). See `../n3ds/docs/O3DS_LABEL_CORRECTIONS.md` and `decrypted_binaries/RENAME_MAP.tsv`. Where older sections of these documents say e.g. "FS 1502", the module is really `am`.

## Quick Reproduction Commands

### Decrypt FIRM and extract kernels (requires `movable.sed`)

```bash
# Decrypt the FIRM title as NCCH
ctrtool -v --intype=ncch --exheader=exh.bin --exefs=exefs.bin title_firm.cxi

# Extract the .firm section
ctrtool -v --exefsdir=exefs_dir title_firm.cxi

# Split FIRM into arm9.bin and arm11.bin
ctrtool -v --intype=firm --firmdir=firm_out --firmtype=nand exefs_dir/firm.bin
```

### Analyze the kernel with radare2

```bash
# Real ARM11 Kernel11 (arm11_section1.bin, runtime base 0xFFF00000)
r2 -a arm -b 32 -m 0xFFF00000 -A decrypted_binaries/kernel/arm11_section1.bin
# Inside r2:
#   afl                        ; list 415 functions
#   pd 100 @ 0xFFF0220C        ; disassemble the SVC dispatcher
#   pd 100 @ 0x1FFAE034        ; entry point (with -m 0x1FF80000)

# ARM9 (base 0x08006800)
r2 -a arm -b 32 -B 0x08006800 -A decrypted_binaries/kernel/arm9.bin
# Inside r2:
#   afl                        ; list functions
#   pd 100 @ 0x0801B01C        ; disassemble the entry point
#   pd 100 @ 0x08007878        ; disassemble the SWI dispatcher
```

### Load friendly symbols in radare2

```bash
# ARM9 with verified names
r2 -a arm -b 32 -B 0x08006800 -i decrypted_binaries/kernel/symbols_arm9_friendly.r2 decrypted_binaries/kernel/arm9.bin

# ARM11 Kernel11 with verified names
r2 -a arm -b 32 -m 0xFFF00000 -i decrypted_binaries/kernel/symbols_arm11_kernel11_friendly.r2 decrypted_binaries/kernel/arm11_section1.bin
```

### Load symbols in Ghidra

1. New project → Import `arm11_section1.bin` or `arm9.bin`
2. **Language:** `ARM:LE:32:v6k` (ARM11) / `ARM:LE:32:v5te` (ARM9)
3. **Image base:** `0xFFF00000` (Kernel11 runtime) / `0x08006800` (ARM9)
4. Run script: `symbols_arm11_kernel11_friendly_ghidra.py` / `symbols_arm9_friendly_ghidra.py`

## Evidence Rules

1. **Facts verified in the binary/disassembly:** only what can be demonstrated directly in the decrypted files (addresses, instructions, cross-references).
2. **Public 3DS knowledge:** documented in 3dbrew/GBATEK, explicitly correlated where applicable without replacing binary verification.
3. **Hypotheses / to be checked:** inferences that need validation on real hardware or further analysis. Never assume them to be true.
4. **Do not invent names:** symbols are only recorded with confirmed semantic names or `EVIDENCE_BASED` (real strings/XREFs); otherwise they use synthetic names and are marked `HYPOTHESIS`.
